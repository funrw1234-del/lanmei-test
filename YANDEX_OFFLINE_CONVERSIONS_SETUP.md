# Офлайн-конверсии в Яндекс.Директ

## Проблема, которую это решает

Обычная цель в Директе засчитывается через счётчик Яндекс.Метрики, который
грузится **в браузере посетителя** (`mc.yandex.ru`). Заявка при этом уходит
через отдельный, серверный канал (Cloudflare Worker) — он не зависит от
браузера клиента и всегда доходит. Если у посетителя стоит блокировщик,
который режет именно Метрику (а не Worker) — заявка приходит вам, а
конверсия в Директе не считается. Клиент и рекламодатель видят разные вещи.

Офлайн-конверсии решают это иначе: сервер сам, по API, напрямую сообщает
Директу «по этому клику была заявка» — без участия браузера посетителя.
Обойти блокировщик тут просто нечем, потому что браузер вообще не участвует.

**Важно:** это работает только для заявок, у которых есть `yclid` — метка
клика по рекламе Директа, которая появляется в URL, когда человек переходит
по рекламному объявлению (`lanmei.ru/?yclid=...`). Прямые заходы, органика,
переходы не с рекламы — `yclid` не имеют, для них не применимо (и не нужно:
там и цели считать не для чего).

---

## 1. Включить приём офлайн-конверсий в Яндекс.Метрике

1. Зайти в [Яндекс.Метрику](https://metrika.yandex.ru) → счётчик **111955901**
2. **Настройки** → **Источники данных** → **Офлайн-конверсии**
3. Включить приём офлайн-данных
4. Там же можно посмотреть/задать имя цели для офлайн-конверсий — по
   умолчанию в коде используется `lead_submitted` (можно оставить это имя
   или задать своё — тогда прописать его в переменной `YANDEX_OFFLINE_GOAL`
   на шаге 3 ниже)

## 2. Связать эту цель с оптимизацией в Директе (по желанию)

Если хотите, чтобы автостратегии Директа учились именно на этих
подтверждённых заявках — в кампаниях выберите эту цель как цель
оптимизации. Не обязательно для самого факта учёта конверсии, но полезно
для эффективности рекламы в целом.

## 3. Токен и переменные в Cloudflare Worker

Тот же самый OAuth-токен, что уже используется в
`C:\Users\Leonold\yandex-direct-lanmei\token.txt` для скрипта статистики,
подходит и здесь (тот же аккаунт Директа, то же приложение «АссистентДирект»).

Cloudflare Dashboard → Workers & Pages → **lanmei-forms** → **Settings →
Variables and Secrets** → Add:

- `YANDEX_DIRECT_TOKEN` — **Secret** — тот же токен из `token.txt` (открой
  файл сам и скопируй оттуда, мне не присылай)
- `YANDEX_OFFLINE_GOAL` — **Variable** (не секрет) — имя цели из шага 1,
  если не `lead_submitted`. Можно пропустить, если оставили имя по умолчанию.

## 4. Задеплоить код Worker'а

`cloudflare-worker/telegram-relay.js` → Cloudflare → **lanmei-forms** →
**Edit code** → вставить актуальный код из репозитория → **Deploy**.

## 5. Проверка

Открыть сайт с фейковым `yclid` в URL, например:
`https://lanmei.ru/?yclid=1234567890testvalue`

Отправить любую форму → в ответе Worker'а (или в логах Cloudflare) будет
поле `offlineConversion`. Если `ok: true` — всё сработало. Если ошибка —
пришли мне точный текст ошибки от Яндекса, скорее всего это несовпадение
названия параметра в JSON (API у Яндекса капризный к точным именам полей),
поправим по тексту.

---

## Что это НЕ чинит

- Уже прошедшие заявки без сохранённого `yclid` — этот механизм появился
  только сейчас, задним числом конверсии не восстановить.
- Прямые заходы и заявки не с рекламы — там `yclid` в принципе нет, это
  нормально, туда офлайн-конверсии не грузятся, потому что нет клика, к
  которому их привязать.
